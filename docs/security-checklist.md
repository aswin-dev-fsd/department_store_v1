## Open, for you

- **Failed logins store the typed username** in the audit log (`auth.login_failed`, `after.username`). That helps spot guessing, but a user who types their password into the username box leaves it in the log. Choose: keep it as it is, or store only whether the username exists.
- **minimatch (moderate, dev-only):** `typescript-eslint` 8.74.0 would fix it. Upgrading needs a check that it still supports TypeScript 6.0 (the pin since Task 1.3). Proposed: accept it until that check is made.
- **Account lockout by the per-username limit** (Task 7.1): 30 wrong passwords lock the account for up to an hour.
- **Production** (rows 3 and 11): cookie flags and HTTPS are checked on the real server in Tasks 7.5 and 7.6, once hosting (PD-03) is decided.
- **Render's `HEAD /` 404 warning** (noted in Checkpoint 1 for this task): not a security measure, so not changed. Proposed: a `HEAD /` answer of 204, or leave it.
